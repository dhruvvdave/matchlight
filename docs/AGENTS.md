# Agent contracts

All agents share one runtime ([`agents/src/runtime`](../agents/src/runtime)):

- **`LlmClient`**: `complete({agent, system, user, schema, tools?, timeoutMs, mock})`. The Azure OpenAI provider uses structured outputs (JSON schema from Zod) and a function-calling loop (up to 4 tool rounds). The mock provider runs the agent's deterministic _mock brain_ with simulated latency.
- **`Tool`**: `{name, description, parameters: ZodSchema, run}`, exported as OpenAI function specs. Tool calls are traced.
- **`Blackboard`**: shared memory with surfaced moments, topic cooldowns, explanations, per-profile feeds.
- **`Tracer`**: every agent step becomes a `TraceSpan {agent, op, status: ok|rejected|fallback|error|skipped, latency_ms, summary, detail}`. Spans are streamed to the UI and logged as JSON (`TRACE_LOG=1`).

## Orchestration flow

[`orchestrator.ts`](../agents/src/orchestrator.ts) wires the agents per session:

1. **Fast path (synchronous):** StatsEngine → Director → Stats agent (facts) → template Explanation → for each profile: Personalizer → Narrator (localised template) → Critic (persona check) → Renderer → Scheduler → publish. Budget < 1.5 s; measured p95 ≈ 4 ms.
2. **Async path** (only for moments the Director marks `explain`): Explainer ⇄ Critic → Narrator (LLM, persona) → Critic → Translator → Critic → publish a feed item that `supersedes` the template line, and update the key card in place. Anything over `NARRATIVE_BUDGET_MS` is discarded (`fallback` span).
3. **Periodic:** momentum bar (every match minute), player-focus updates (every 10 min), metric badge (throttled), recap at full time for every language in use.

## Microsoft Agent Framework workflow

[`agents-maf/matchlight_maf/workflow.py`](../agents-maf/matchlight_maf/workflow.py):

```
ExplainRequest ─► ExplainerExecutor (MAF Agent + Azure OpenAI chat client) ─Draft─► CriticExecutor
                         ▲                                                           │
                         └──────────────── CriticFeedback (rejected) ◄───────────────┘
                                                                                     ▼ yield_output(ExplainResult)
```

Built with `WorkflowBuilder(start_executor=explainer).add_edge(explainer, critic).add_edge(critic, explainer)`. The regeneration loop is a real workflow cycle bounded by `max_attempts`. Workflow events are returned to the TS orchestrator and appear in the Agent Trace panel as `maf:draft`, `maf:groundedness` and `maf:redraft #n`. The TS Critic re-verifies the result before anything is published.

## Honest limits

- The offline mock LLM is a deterministic stand-in: it rephrases grounded explanations and **deliberately injects errors** into about 20% of first drafts (`MOCK_HALLUCINATION_RATE`) so the Critic loop is visible without cloud keys. It is labelled `mock` everywhere.
- Offline translation is not machine translation. Non-English lines come from hand-written localised templates. Free-form LLM narratives in other languages need Azure AI Translator (or Azure OpenAI).
- The auto-eventing stub works on 1 Hz synthetic tracking: about 58% precision and 43% recall on passes. It's a pathway demonstration, not a product.
